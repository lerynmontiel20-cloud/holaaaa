# 🎙️ Agenda de la Radio Escolar

**Proyecto individual:** Agenda de la radio escolar  
**Asignatura:** Software y Laboratorio — Bachillerato Técnico en Informática (BTI)  
**Institución:** Colegio Nacional EMD Asunción Escalada[cite: 1]  
**Autora:** Aylin Montiel (Leryn Montiel)[cite: 1]

---

## 📌 Descripción del proyecto

Aplicación web desarrollada para que el equipo de la radio escolar organice la programación y consulte las emisiones por género[cite: 1]. Permite crear, listar, modificar y eliminar registros con persistencia de datos en **Supabase**, control de versiones en **GitHub** y publicación en **Render**[cite: 1].

### Estructura de la tabla en Supabase (`agenda_radio`)
- `id`: clave primaria autoincremental (`BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`).
- `programa`: nombre del programa (`TEXT NOT NULL`).
- `genero`: género de la emisión (`TEXT NOT NULL`), incluyendo opciones como `musical` y `entrevista`[cite: 1].
- `alias_conductor`: alias del conductor (`TEXT NOT NULL`).
- `fecha`: fecha de emisión (`DATE NOT NULL`).
- `duracion_minutos`: duración en minutos (`INTEGER NOT NULL`).

## 🤖 Uso de Inteligencia Artificial

### 1. Consulta realizada a la IA
> *"¿Cómo estructurar una tabla en Supabase con clave primaria para una agenda de radio escolar y permitir operaciones CRUD (crear, leer, actualizar y eliminar) desde JavaScript puro sin que bloqueen las políticas de seguridad?"*

### 2. Sugerencia aplicada o corregida
- **Base de datos y permisos:** Se aplicó la creación de la tabla `agenda_radio` con clave primaria (`PRIMARY KEY`) y tipos de datos adecuados (`TEXT`, `DATE`, `INTEGER`). Para evitar bloqueos al leer, insertar, editar o borrar desde el navegador, se activó Row Level Security (RLS) con una política pública para el entorno de prueba del examen[cite: 1].
- **Filtro y edición:** Se implementó el filtrado por género consultando a Supabase con `.eq('genero', valor)` cuando se selecciona un género distinto de "todos", y se vinculó el formulario para cargar un registro existente y actualizarlo por su `id`.

### 3. Cómo se comprobó el resultado
1. **Registros iniciales y persistencia (Indicador 5):** Se cargaron tres registros ficticios incluyendo `musical` y `entrevista`[cite: 1]. Al recargar la página (`F5`), se comprobó que los datos siguen guardados en Supabase[cite: 1].
2. **Crear y listar (Indicador 1):** Se registró un nuevo programa desde el formulario y se verificó que aparezca en la tabla de programación[cite: 1].
3. **Modificar (Indicador 2):** Se editó un registro existente (cambiando datos como nombre, conductor, duración o género) y se comprobó que la tabla muestre los valores actualizados y persistan al recargar[cite: 1].
4. **Eliminar (Indicador 3):** Se eliminó un registro desde su botón correspondiente y se verificó que desaparezca de la lista y de la base de datos[cite: 1].
5. **Filtro por género (Indicador 4):** Se probó filtrar por `musical` y por `entrevista` confirmando que solo se muestran las filas que coinciden con el género elegido[cite: 1].
6. **Repositorio y publicación (Indicadores 7 y 8):** Se subió el código a este repositorio de GitHub mediante un commit propio y se desplegó como Static Site en Render, comprobando que el enlace público abre y carga los datos desde Supabase[cite: 1].
